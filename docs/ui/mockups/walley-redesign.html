Static review mockup. Not wired to the app. Frames use container queries, so each frame behaves like a viewport of its own width (the 768px dual-pane breakpoint from spec section 7). Frames marked "pinned" always show one theme; all others follow the toggle above (dark by default).

(a) Sync Dashboard

One compact line per item: name, cycle, mono amount, one visible action. The action depends on the situation: Link (indigo outline) when a candidate exists, otherwise Create in .... Ignore and Restore live in the "more" menu (reversible, so no confirm). Only Run Sync Check is a filled button. Dark and light shown, both pinned.

(a) Dashboard states

Sync failure names the side, offers Retry and a link to the matching Settings section, and keeps the last good result, marked stale. First use shows setup steps instead of an empty page. Danger red is used for errors only; amber is reserved for Mismatch.

Columns pair each name with its amount. Sticky two-level header, first column sticky on narrow widths, search, counts, and a Run Sync Check on this page so it is never empty with no way forward. Review appears on Mismatch rows only. Ignored items live in their own section.

(b) Diff modal

The modal stays open and shows "Working..." until the server answers; the long dialog scrolls internally with a pinned footer.

(d) Settings

Section cards with in-page anchor nav (a labelled Select below 768px). Each card carries a scope label. Save models: General (This device) saves instantly with an inline "Saved" status; every Your-account card has one footer Save that commits everything in that card, including the budget pick and tolerance. Test connection and Load budgets use the values currently typed (needs backend confirmation, see note). Secrets are write-only.

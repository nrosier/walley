# src/server/routes

Fastify route plugins, registered by `buildApp` in `../app.ts` under the `/api` prefix. Every route here is default-deny unless it sets `config: { public: true }`.

| Path | What it is | Read it when |
| --- | --- | --- |
| `health.ts` | `GET /api/health` returns `{ "status": "ok" }`. Public | Health checks, or an example of a public route |
| `auth.ts` | `authRoutes`: public `GET /api/auth/config` (`{ mode, registration }`), `GET /api/auth/me` (`{ email, authMethod }`, session required), and public `POST /api/auth/register` (always 202 `{status:"verification_sent"}` with no cookie, 400 `invalid_request`, 403 `registration_disabled` / `local_auth_disabled`), public `POST /api/auth/verify-email` (204 no cookie, 400 `invalid_request` / `invalid_token`, 403 `local_auth_disabled`; per-IP limit), and an unverified user's login gets the same 401 and `POST /api/auth/login` (200, 400 `invalid_request`, 401 `invalid_credentials`, 403 `local_auth_disabled`). Both return 429 `rate_limited` with `Retry-After` once an email (5 per 15 min, shared by both) or a client IP (20 per 15 min) is over its limit. Needs `secureCookies`, `now`, `mailer` and `publicOrigin` options from `app.ts`. Uses `auth/passwords.ts`, `auth/sessions.ts`, `db/accounts.ts`, `db/lookup.ts` | Changing what the browser learns about auth or the signed-in user |
| `auth-local.test.ts` | Tests for `POST /api/auth/register` and `/login`: 202 contract, error codes, identical 401s, the session a register request carries is left alone, OIDC refusal without a database read, two-user isolation | Changing local sign-in |
| `auth-verify.test.ts` | Tests for `POST /api/auth/verify-email` (204, reuse, expiry, bad input, OIDC refusal), login before and after verification, re-register rules (unverified: hash kept, new link, old token valid), email shape (400), mail per branch, a failing mailer, no secrets in logs or on a database error, one Argon2 derivation per register path | Changing verification or registration |
| `auth-logout.test.ts` | Tests for `POST /api/auth/logout` and the session hook's cookie clearing | Changing logout or the session hook |
| `auth-rate-limit.test.ts` | Tests for the 429 limits on register and login: per email, shared counter, success clears, per IP, `trustProxy`, no Argon2 work when limited | Changing sign-in limits |
| `auth-gate.test.ts` | Tests for default-deny: 401 on every non-public route, public routes, mode-mismatched sessions; through `buildApp`, the account and settings routes (401/200, CSRF 403, tolerance boundaries, two-user isolation, settings routes absent without `settings`) | Changing the deny hook or adding a route |
| `oidc.ts` | `registerOidcRoutes(app, { db, secureCookies, allowRegistration, now, oidc })`: public `GET /api/auth/oidc/login` (302 to the provider, sealed `walley_oidc` cookie, per-IP rate limit with its own counters, 429 `rate_limited`) and `GET /api/auth/oidc/callback` (clears the flow cookie, verifies, `resolveOidcLogin`, 302 to `/`, `/login?error=account_not_linked` or `/login?error=oidc_failed`). Both answer 404 when `oidc` is null (local mode). Wired in `app.ts` | Changing OIDC sign-in redirects |
| `oidc.test.ts` | Route tests with a fake provider: 404 in local mode, flow cookie, failure paths, linking, creation, session replacement, two-user isolation, login rate limit | Changing `oidc.ts` |
| `integrations.ts` | `integrationRoutes` with `{ deps: CreateDeps }`: `POST /api/integrations/actual-schedules` (body `wallosSubscriptionId`, `accountId`, `payee`, `categoryId?`; 201 ids and flags) and `POST /api/integrations/wallos-subscriptions` (body `scheduleId`; 201 `wallosSubscriptionId`). Fixed error codes only. Registered in `app.ts` when `BuildAppOptions.integrations` is set. Uses `../integrations/create.ts` | Changing the create routes or their error mapping |
| `integrations.test.ts` | 401, CSRF, body validation, two-user isolation and no-secret error mapping for the create routes | Changing `integrations.ts` |
| `sync.ts` | `syncRoutes` with `{ deps: SyncCheckDeps }`: `POST /api/sync/check` (no body, user from the session; 200 `SyncCheckResult` from `src/lib/sync-check-types.ts`: `{ checkedAt, baseCurrency, unlinkedWallos, unlinkedActual, candidates, mismatches, unmappable, orphaned, linked, ignored }`). Reuses `sendFailure` from `integrations.ts`, so the error codes are the same fixed set. Registered in `app.ts` next to `integrationRoutes` (needs `BuildAppOptions.integrations`). Uses `../matching/sync-check.ts` | Changing the Sync Check route |
| `sync.test.ts` | 401, CSRF, Origin, response keys, no writes to Wallos or Actual, two-user isolation, `wallos_auth_failed` and `internal_error` without secret text | Changing `sync.ts` |
| `matches.ts` | `matchesRoutes` with `{ deps: Pick<CreateDeps, 'wallos' | 'repoFor' | 'withActual'> }`: `POST /api/matches/:id/resolve` (body `action`, `confirm?`). Built: `ignore_diff` (MISMATCH_DETECTED only, re-reads both sides read-only via `readCurrentSides` in `../matching/sync-check.ts`, then in one update sets LINKED and stores the server-computed current hashes; 400 `invalid_state` and no write if a side is missing or unhashable; client hashes are never used) and `unlink` (needs `confirm: true`, LINKED or MISMATCH_DETECTED, deletes the row). Other actions, including held `overwrite_wallos` / `overwrite_actual`, give 400 `unsupported_action`. Also 400 `invalid_request` / `confirmation_required` / `invalid_state`, 404 `match_not_found`. Reads only, never writes to Wallos or Actual. Registered in `app.ts` next to `syncRoutes` | Changing the resolve route |
| `matches.test.ts` | 401, CSRF, Origin, each action and error code, held actions call nothing, ignore_diff stores current hashes and a later sync check is clean, no write spies called, two-user isolation | Changing `matches.ts` |
| `account.ts` | `accountRoutes` with `{ db, mode }`: `GET /api/account` (`{ email, mode, hasPassword, identities }`) and `PUT /api/account/password` (body `currentPassword`, `newPassword`; 204, 400 `invalid_request`, 401 `invalid_credentials`, 403 `local_auth_disabled` in OIDC mode; deletes the user's other sessions). Registered by `app.ts` whenever `auth` is set | Changing account settings |
| `account.test.ts` | 401, CSRF, Origin, password change rules, OIDC refusal, session cleanup, two-user isolation (through `buildApp`) | Changing `account.ts` |
| `settings-wallos.ts` | `settingsWallosRoutes` with `{ deps: SettingsWallosDeps }` (`repoFor`, `wallos: Pick<WallosClient, 'listCurrencies'>`, `appSecret`): `GET /api/settings/wallos` (`{ wallosUrl, hasWallosApiKey }`, never the key), `PUT` (body `wallosUrl`, `apiKey?`; key encrypted on save, empty keeps the stored key; 400 `invalid_request` / `invalid_url`) and `POST /api/settings/wallos/test` (saved credentials only; fixed codes via `sendFailure`). Registered by `app.ts` when `BuildAppOptions.settings` is set | Changing Wallos settings |
| `settings-wallos.test.ts` | 401, CSRF, Origin, key never returned, URL validation, test-connection error mapping, two-user isolation (through `buildApp`) | Changing `settings-wallos.ts` |
| `settings-matching.ts` | `settingsMatchingRoutes` with `{ deps: { repoFor } }`: `GET /api/settings/matching` (`{ tolerancePercent }`, 5 when no row) and `PUT` (body `tolerancePercent`: finite number 0 to 50 inclusive; 200 saved value, 400 `invalid_request` for wrong type or unparseable body, 400 `out_of_range`). Writes through `repo.upsertConfig`. Exports `checkTolerance`. Registered by `app.ts` when `BuildAppOptions.settings` is set | Changing matching settings |
| `settings-matching.test.ts` | `checkTolerance` unit cases, 401, CSRF, Origin, default, boundaries, no write on rejection, two-user isolation | Changing `settings-matching.ts` |
| `settings-actual.ts` | `settingsActualRoutes` with `{ deps: SettingsActualDeps }` (`repoFor`, `appSecret`, `withActualServer`, `withActual`): `GET /api/settings/actual` (`{ actualUrl, actualBudgetId, hasActualPassword, hasActualSyncKey }`), `PUT` (body `actualUrl`, `password?`, `syncKey?`, `clearSyncKey?`, `actualBudgetId?`; 400 `invalid_url` / `invalid_request` / `password_required` when the URL changes and no password is sent; blank secrets keep the stored value; a URL change clears the budget id), `POST /budgets` (saved credentials, `{ budgets: [{ id, name }] }` via `withActualServer` + `listBudgets`) and `POST /base-currency` (`{ currency }` via `withActual` + `readBaseCurrency`, not stored). Secrets are encrypted with `deriveUserKey` + `encryptSecret` and never returned. Errors go through `sendFailure` (`actual_not_configured` 400, `actual_unavailable` 502); library errors inside the session are replaced by a fixed one. Not yet registered in `app.ts` | Changing Actual settings or the budget picker |
| `settings-actual.test.ts` | Body keys and no plaintext secrets, blank keeps, `clearSyncKey`, URL change, invalid URL, budgets and base-currency with fakes, error mapping without secret text, 401, CSRF, Origin, two-user isolation | Changing `settings-actual.ts` |
| `service-url.ts` | `validateServiceUrl(raw)`: https, or http on loopback only, no credentials, query or fragment. Shared by the Wallos and Actual settings; `validateWallosUrl` in `settings-wallos.ts` is an alias | Changing URL rules for outside services |

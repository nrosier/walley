# src/server/routes

Fastify route plugins, registered by `buildApp` in `../app.ts` under the `/api` prefix. Every route here is default-deny unless it sets `config: { public: true }`.

| Path | What it is | Read it when |
| --- | --- | --- |
| `health.ts` | `GET /api/health` returns `{ "status": "ok" }`. Public | Health checks, or an example of a public route |
| `auth.ts` | `authRoutes`: public `GET /api/auth/config` (`{ mode, registration }`), `GET /api/auth/me` (`{ email, authMethod }`, session required), and public `POST /api/auth/register` (always 202 `{status:"verification_sent"}` with no cookie, 400 `invalid_request`, 403 `registration_disabled` / `local_auth_disabled`), public `POST /api/auth/verify-email` (204 no cookie, 400 `invalid_request` / `invalid_token`, 403 `local_auth_disabled`; per-IP limit), and an unverified user's login gets the same 401 and `POST /api/auth/login` (200, 400 `invalid_request`, 401 `invalid_credentials`, 403 `local_auth_disabled`). Both return 429 `rate_limited` with `Retry-After` once an email (5 per 15 min, shared by both) or a client IP (20 per 15 min) is over its limit. Needs `secureCookies`, `now`, `mailer` and `publicOrigin` options from `app.ts`. Uses `auth/passwords.ts`, `auth/sessions.ts`, `db/accounts.ts`, `db/lookup.ts` | Changing what the browser learns about auth or the signed-in user |
| `auth-local.test.ts` | Tests for `POST /api/auth/register` and `/login`: 202 contract, error codes, identical 401s, the session a register request carries is left alone, OIDC refusal without a database read, two-user isolation | Changing local sign-in |
| `auth-verify.test.ts` | Tests for `POST /api/auth/verify-email` (204, reuse, expiry, bad input, OIDC refusal), login before and after verification, re-register rules (unverified: hash kept, new link, old token valid), email shape (400), mail per branch, a failing mailer, no secrets in logs or on a database error, one Argon2 derivation per register path | Changing verification or registration |
| `auth-logout.test.ts` | Tests for `POST /api/auth/logout` and the session hook's cookie clearing | Changing logout or the session hook |
| `auth-rate-limit.test.ts` | Tests for the 429 limits on register and login: per email, shared counter, success clears, per IP, `trustProxy`, no Argon2 work when limited | Changing sign-in limits |
| `auth-gate.test.ts` | Tests for default-deny: 401 on every non-public route, public routes, mode-mismatched sessions | Changing the deny hook or adding a route |
| `oidc.ts` | `registerOidcRoutes(app, { db, secureCookies, allowRegistration, now, oidc })`: public `GET /api/auth/oidc/login` (302 to the provider, sealed `walley_oidc` cookie, per-IP rate limit with its own counters, 429 `rate_limited`) and `GET /api/auth/oidc/callback` (clears the flow cookie, verifies, `resolveOidcLogin`, 302 to `/`, `/login?error=account_not_linked` or `/login?error=oidc_failed`). Both answer 404 when `oidc` is null (local mode). Wired in `app.ts` | Changing OIDC sign-in redirects |
| `oidc.test.ts` | Route tests with a fake provider: 404 in local mode, flow cookie, failure paths, linking, creation, session replacement, two-user isolation, login rate limit | Changing `oidc.ts` |

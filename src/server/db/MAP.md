# src/server/db

SQLite database for Walley, via better-sqlite3 and Drizzle ORM. The database file is at `DATABASE_PATH`.

## Rule: user data goes through `createUserRepo`

Every read, update and delete of user-owned rows goes through `createUserRepo(db, userId)` in `repo.ts`. The factory binds the user id once, so each query is scoped to that user. ESLint blocks `drizzle-orm` imports everywhere under `src/server` except this folder, so the factory is the only way in.

There are two exceptions. `createUser` in `accounts.ts` is the only unscoped write: creating a user creates the scope, so it cannot be bound to an existing user. `lookup.ts` holds the only unscoped reads, the five read-only lookups that sign-in needs and the email verification link needs before a user id is known (owner decision O2). Nothing else may be added to either file; `exports.test.ts` pins both export lists. Session and identity writes are not exceptions: they are `UserRepo` methods, scoped to the bound user.

## Files

| Path | Exports | Read it when |
| --- | --- | --- |
| `schema.ts` | Tables `users` (nullable `emailVerifiedAt`), `userIdentities`, `sessions`, `emailVerifications`, `userConfigs`, `matches`, `subscriptionOverrides` (per-subscription exchange-rate override, `rate` as text), `overwriteSnapshots` (pre-overwrite copy of a Wallos subscription or Actual schedule as JSON, scoped by `user_id`, `match_id` has no FK); row types `UserRow`, `UserIdentityRow`, `SessionRow`, `EmailVerificationRow`, `UserConfigRow`, `MatchRow`, `NewMatchRow`, `SubscriptionOverrideRow`, `OverwriteSnapshotRow` | Changing a column, index or CHECK |
| `client.ts` | `AppDatabase` type, `MIGRATIONS_FOLDER`, `openDatabase(path)`, `closeDatabase(db)` | Startup, or the connection pragmas |
| `repo.ts` | `createUserRepo(db, userId)`, plus the `UserRepo`, `UserConfigInput`, `MatchInput`, `MatchPatch` and `SessionInput` and `EmailVerificationInput` types. Email verification methods: `createEmailVerification` (prunes this user's expired tokens), `consumeEmailVerification` (single-use, unexpired, false for a null pending hash; verifies the user, applies the token's `pendingPasswordHash` to an unverified user and deletes all the user's tokens; the route checks the password first), `deleteEmailVerification` (burns one token); `pendingPasswordHash` is required on create, `markEmailVerified` (OIDC link; optional hash clear; drops tokens). Session methods: `getEmail`, `createSession` (also prunes this user's expired sessions), `touchSession`, `deleteSession`, `linkIdentity` (false on a unique conflict). Match lookup: `findMatchByItem(side, itemId)` (user-scoped SQL, checks the Wallos or Actual id). Override methods: `getSubscriptionOverride`, `listSubscriptionOverrides`, `upsertSubscriptionOverride` (validates the rate with `parseRate`), `saveSubscriptionOverride` (upsert plus, only when the rate changed, one-transaction reset of this user's LINKED `last_known_wallos_hash`; returns `{ override, changed, resetMatchIds }`), `clearSubscriptionOverride` (delete plus the same reset), `deleteSubscriptionOverride` (no reset). Snapshot methods: `insertOverwriteSnapshot`, `listOverwriteSnapshots` | Reading or writing a user's config, matches, sessions, identities or subscription overrides |
| `lookup.ts` | `findSessionByIdHash`, `findEmailVerification` (the only token-keyed read; returns `{ userId, email, emailVerified, pendingPasswordHash }`), `findLoginByEmail` (trims and lowercases; returns `emailVerified`), `findUserIdByIdentity`, `findLinkCandidate` (email match with no identity at the issuer; returns `{ id, emailVerified }`). Read-only; the only unscoped reads | Sign-in, before a user id is known |
| `cleanup-unverified.ts` | `cleanupUnverifiedPasswords(sqlite, apply)` and `countLegacyRows`: the logic of the one-off `scripts/cleanup-unverified-passwords.ts` (`npm run db:cleanup-unverified`; dry run unless `--apply`). Raw SQL over all users; never called by the app or the migrations. Test: `cleanup-unverified.test.ts` | Running or changing the legacy cleanup |
| `accounts.ts` | `createUser(db, { email, passwordHash, verifiedAt? })`, the only unscoped write; OIDC-created users are written verified, local ones unverified | Creating a user |
| `migrations/` | The committed Drizzle migrations (`0000_init.sql`, `0001_sessions.sql`, `0002_email_verifications.sql`, `0003_backfill_email_verified.sql`, `0004_subscription_overrides.sql`, `0005_overwrite_snapshots.sql`, `0006_email_verification_pending_hash.sql`) and their `meta/` journal. Generated by `npm run db:generate`; never edit by hand | Schema history, or the CI drift guard |
| `*.test.ts` | Tests for each module, including `tenant-isolation.test.ts` and `exports.test.ts` (fails if an export is added) | Adding a query or a table |

## Notes

- `openDatabase` turns on `foreign_keys` and `busy_timeout`. A file database also uses WAL.
- Migrations run at startup and are recorded in `__drizzle_migrations`. A second start runs none.
- `sessions.id` is the hex SHA-256 of the session token, never the token. `csrf_hash` is the SHA-256 of the CSRF token. Lookups go by primary key.
- Secrets in `user_configs` are stored encrypted (see `src/server/crypto/MAP.md`), never as plaintext.

# src/server/db

SQLite database for Walley, via better-sqlite3 and Drizzle ORM. The database file is at `DATABASE_PATH`.

## Rule: user data goes through `createUserRepo`

Every read, update and delete of user-owned rows goes through `createUserRepo(db, userId)` in `repo.ts`. The factory binds the user id once, so each query is scoped to that user. ESLint blocks `drizzle-orm` imports everywhere under `src/server` except this folder, so the factory is the only way in.

There are two exceptions. `createUser` in `accounts.ts` is the only unscoped write: creating a user creates the scope, so it cannot be bound to an existing user. `lookup.ts` holds the only unscoped reads, the four read-only lookups that sign-in needs before a user id is known (owner decision O2). Nothing else may be added to either file; `exports.test.ts` pins both export lists. Session and identity writes are not exceptions: they are `UserRepo` methods, scoped to the bound user.

## Files

| Path | Exports | Read it when |
| --- | --- | --- |
| `schema.ts` | Tables `users`, `userIdentities`, `sessions`, `userConfigs`, `matches`; row types `UserRow`, `UserIdentityRow`, `SessionRow`, `UserConfigRow`, `MatchRow`, `NewMatchRow` | Changing a column, index or CHECK |
| `client.ts` | `AppDatabase` type, `MIGRATIONS_FOLDER`, `openDatabase(path)`, `closeDatabase(db)` | Startup, or the connection pragmas |
| `repo.ts` | `createUserRepo(db, userId)`, plus the `UserRepo`, `UserConfigInput`, `MatchInput`, `MatchPatch` and `SessionInput` types. Session methods: `getEmail`, `createSession` (also prunes this user's expired sessions), `touchSession`, `deleteSession`, `linkIdentity` (false on a unique conflict) | Reading or writing a user's config, matches, sessions or identities |
| `lookup.ts` | `findSessionByIdHash`, `findLoginByEmail` (trims and lowercases), `findUserIdByIdentity`, `findLinkCandidate` (email match with no identity at the issuer). Read-only; the only unscoped reads | Sign-in, before a user id is known |
| `accounts.ts` | `createUser(db, { email, passwordHash })`, the only unscoped write | Creating a user |
| `migrations/` | The committed Drizzle migrations (`0000_init.sql`, `0001_sessions.sql`) and their `meta/` journal. Generated by `npm run db:generate`; never edit by hand | Schema history, or the CI drift guard |
| `*.test.ts` | Tests for each module, including `tenant-isolation.test.ts` and `exports.test.ts` (fails if an export is added) | Adding a query or a table |

## Notes

- `openDatabase` turns on `foreign_keys` and `busy_timeout`. A file database also uses WAL.
- Migrations run at startup and are recorded in `__drizzle_migrations`. A second start runs none.
- `sessions.id` is the hex SHA-256 of the session token, never the token. `csrf_hash` is the SHA-256 of the CSRF token. Lookups go by primary key.
- Secrets in `user_configs` are stored encrypted (see `src/server/crypto/MAP.md`), never as plaintext.

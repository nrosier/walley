# src/server/db

SQLite database for Walley, via better-sqlite3 and Drizzle ORM. The database file is at `DATABASE_PATH`.

## Rule: user data goes through `createUserRepo`

Every read, update and delete of user-owned rows goes through `createUserRepo(db, userId)` in `repo.ts`. The factory binds the user id once, so each query is scoped to that user. ESLint blocks `drizzle-orm` imports everywhere under `src/server` except this folder, so the factory is the only way in.

The one exception is `createUser` in `accounts.ts`. Creating a user creates the scope, so it cannot be bound to an existing user. Nothing else may be added to that file.

## Files

| Path | Exports | Read it when |
| --- | --- | --- |
| `schema.ts` | Tables `users`, `userIdentities`, `userConfigs`, `matches`; row types `UserRow`, `UserIdentityRow`, `UserConfigRow`, `MatchRow`, `NewMatchRow` | Changing a column, index or CHECK |
| `client.ts` | `AppDatabase` type, `MIGRATIONS_FOLDER`, `openDatabase(path)`, `closeDatabase(db)` | Startup, or the connection pragmas |
| `repo.ts` | `createUserRepo(db, userId)`, plus the `UserRepo`, `UserConfigInput`, `MatchInput` and `MatchPatch` types | Reading or writing a user's config or matches |
| `accounts.ts` | `createUser(db, { email, passwordHash })`, the only unscoped write | Creating a user |
| `migrations/` | The committed Drizzle migration (`0000_init.sql`) and its `meta/` journal. Generated by `npm run db:generate`; never edit by hand | Schema history, or the CI drift guard |
| `*.test.ts` | Tests for each module, including `tenant-isolation.test.ts` and `exports.test.ts` (fails if an export is added) | Adding a query or a table |

## Notes

- `openDatabase` turns on `foreign_keys` and `busy_timeout`. A file database also uses WAL.
- Migrations run at startup and are recorded in `__drizzle_migrations`. A second start runs none.
- Secrets in `user_configs` are stored encrypted (see `src/server/crypto/MAP.md`), never as plaintext.

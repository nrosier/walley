# src/server/matching

Server side of match detection. Pure matching rules live in `src/lib` (`name-match.ts`, `amount-match.ts`, `match-fields.ts`, `match-badge.ts`).

- `hash.ts`: `sha256Hex(canonicalString)` via `node:crypto`, and `hashMatchFields(input)` (null for pattern schedules; name case ignored, as `normalizeMatchFields` lowercases it). Values go to `matches.last_known_wallos_hash` and `last_known_actual_hash`.
- `hash.test.ts`: tests for `hash.ts`.
- `engine.ts`: `classifySavedPairs(savedMatches, wallosIds, actualIds)`, pure. Classifies saved pairs as `linked`, `orphaned_wallos`, `orphaned_actual` or `orphaned_both` (computed, not stored), preserves ignored rows, and lists unlinked Wallos and Actual ids.
- `engine.test.ts`: tests for `engine.ts`.
- `mismatch.ts`: `detectMismatches(savedRows, currentByWallosId, currentByActualId, legacyByWallosId?)`, pure. A Wallos hash that differs only by the pre-decode (0.2.0 raw-name) hash from `legacyByWallosNameFields` (in `../integrations/wallos/map.ts`) is re-baselined (`wallosRebaselined`), not drift. Hashes with `hashMatchFields` (name case is ignored in the shared canonical form). Per LINKED or MISMATCH_DETECTED pair returns `nextStatus`, the hashes to store (`wallosHash`, `actualHash`; the stored baseline on drift, the current hash when the stored one was null), the current hashes, drift flags and `baseline`. Skips ignored and orphaned rows; lists pattern schedules in `unmappable`. A mismatch whose drift is gone returns to LINKED.
- `mismatch.test.ts`: tests for `mismatch.ts`.
- `sync-check.ts`: `runSyncCheck(deps, userId)` (#39, #35, #38). Reads config, matches and overrides through the scoped repo, the Wallos subscriptions and currencies, and the Actual schedules and base currency; maps both sides (Wallos converted to base, range schedules by midpoint with `isRange`, pattern schedules `unmappable`); classifies saved pairs, runs `detectMismatches`, and writes only changed `status` / hashes through `updateMatch`. Candidates use the exported pure `isCandidate(wallosItem, actualItem, tolerance)`: name (`nameScore` >= threshold) and amount (`amountWithinTolerance`, user tolerance, default 5). Each unlinked item (`unlinkedWallos`, `unlinkedActual`) carries an optional `cycle` (`{ key, count }` from `billingCycleOf` in `src/lib/billing-cycle.ts`, #136; absent when unmappable; never on linked or ignored rows). Returns `SyncCheckResult` `{ checkedAt, baseCurrency, unlinkedWallos, unlinkedActual, candidates, mismatches (with `matchId`), unmappable, orphaned, linked, ignored }`; `linked` lists LINKED / MISMATCH_DETECTED rows with `orphan`, display fields (null for a missing side) and `relinkCandidateIds` (for an orphaned row, unlinked missing-side ids passing `isCandidate` against the survivor, best name score first; empty otherwise), `ignored` lists IGNORED_* rows with display fields; both are read-only. The `Sync*` types live in `src/lib/sync-check-types.ts` and are re-exported here. Deps injected (`wallos`, `repoFor`, `withActual`, `now`, optional `cache`). With `deps.cache` the sync check reads the Wallos subscriptions and currencies and the Actual schedules and base currency through the per-user `UpstreamCache` (five minutes); `runSyncCheck(deps, userId, { refresh: true })` bypasses it. Write paths call `readCurrentSides` without a cache, so the hashes they store are always from a live read. Also exports `readCurrentSides(deps, userId)` (returns `{ wallosSides, actualSides, baseCode }`; H14: a Wallos item with no `start_date` is hashed with its row's `firstSeenNextPayment` anchor, a row with no anchor yet gets it written once, and an item with no row uses `next_payment` for that read and exposes it as `Side.anchorDate` so the link route and `linkCreatedPair` store it on insert) and `fieldInputsOf(sides)`, shared by `runSyncCheck` and the ignore_diff branch of `../routes/matches.ts`. Used by `../routes/sync.ts`.
- `sync-check-cache.test.ts`: tests for the cache in `runSyncCheck` (TTL, refresh, invalidate, two users, no credentials stored).
- `overwrite.ts`: `overwriteWallos` / `overwriteActual(deps, userId, match, now)` (#54), used by the resolve route. Return `"written"` or `"no_change_needed"` (nothing differed: no snapshot, no write, match stays MISMATCH_DETECTED). A per-match in-flight guard and a status re-check right before the snapshot throw `CreateFlowError("invalid_state")` on a double confirm. Actual date changes call `updateSchedule(id, fields, true)`. Read both sides, refuse range and pattern schedules, build only the changed fields, `insertOverwriteSnapshot` the target, write (`wallos.updateSubscription` with `id` + `next_payment` + changed fields, or `api.updateSchedule` then `api.sync`), re-read via `readCurrentSides`, store server hashes and LINKED. Throws `OverwriteReadbackError` when the re-read cannot be hashed.
- `link-created.ts`: `linkCreatedPair(deps, userId, wallosId, actualScheduleId)` (#108), used by `../routes/integrations.ts` after a successful create. Returns the existing match (`matchCreated: false`) when one already covers either item; otherwise re-reads both sides with `readCurrentSides`, hashes with `hashMatchFields` and inserts a LINKED row through the scoped repo. A failed read-back stores null hashes (baselined on the next Sync Check) rather than failing the create.
- `relink-orphan.ts`: `checkRecreate(deps, userId, matchId, target, sourceId)` and `repointAfterRecreate(deps, userId, row, target, newItemId)` (#109), used by the create routes when the body has `matchId`. The check throws `CreateFlowError` (`match_not_found`, `invalid_state`) unless the user's row is LINKED/MISMATCH_DETECTED, the source id is its surviving id, and `readCurrentSides` shows survivor present and target absent. The repoint re-reads, hashes like `link-created.ts` (failed read: null hashes) and calls `replaceMatchSide`; returns its boolean.
- `sync-check.test.ts`: tests for `sync-check.ts` with fake clients and an in-memory database.
